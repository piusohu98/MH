# OCR 基线数据集

阶段 3.2 使用 `ocr-dataset-v1` 管理本地 OCR 调试样本。它与 `offline-replay-v1` 分开：OCR 数据集只描述图片、页面类别和人工可见标签，不包含真实区服、采集时间或数量，因此不能直接写入行情 SQLite，也不能驱动物价趋势分析。

## 输入范围

当前输入目录为 `_input/step1-web-candidates`，由用户提供的公开网页候选截图和审核 CSV 组成。该目录被 `.gitignore` 忽略，不会随源代码提交。图片主要用于：

- 页面分类边界：摆摊列表、商城、搜索/分类、出售弹窗、电脑版界面和未知页面。
- 商品名与价格 OCR 的离线调试。
- 低置信度、遮挡、水印、旧版布局和负样本的安全降级。

公开网页图片不代表当前客户端版本。没有当前版本截图、中文模型和行级标注前，不输出真实识别率或 P95 结论。

## 生成索引

在仓库根目录执行：

```powershell
pwsh -File scripts/Prepare-OcrDataset.ps1 `
  -Root _input/step1-web-candidates
```

脚本默认生成 `_input/step1-web-candidates/ocr-dataset-v1.json`。它会：

- 读取 `review-confirmed.csv`，只接受“保留=是”的记录。
- 校验图片路径位于输入目录内、扩展名受支持、文件存在且 SHA-256 与审核记录一致。
- 将“正样本/辅助样本/负样本”归一化为 `positive/auxiliary/negative`。
- 要求正样本必须是 `MarketList`，且带非空商品名和价格标签。
- 按 SHA-256 去重；相同图片的关键标签冲突时直接失败。
- 明确写入 `SourceKind=public-web-debug-only`，阻止误解为真实行情数据。

输出索引只允许作为 OCR 基线输入。`RecommendedForOcr=true` 表示可进入商品名/价格识别调试，不表示可以进入 Server 或交易行情。

## 当前门槛

现有审核表记录了 41 张正样本，去重后还需要补充当前版本样本，尤其是三级药、烹饪、临时符/制造符、低级兽诀/法宝精华、珍品召唤灵和装备。遮挡、旧版界面和水印样本应单独作为困难集，不能与清晰样本混为一个准确率数字。

真实 OCR 适配前仍需：

1. 合法可分发的 RapidOcrNet 中文模型文件和版本记录。
2. 商品别名字典及行级商品名/价格区域标注。
3. 当前游戏版本的正样本和页面负样本。
4. 登录、更新、验证码、掉线、未知页面截图，用于停止操作通知测试。

任何模型接入都必须保持本地处理、低置信度人工复核、截图不上传和不执行游戏输入。
